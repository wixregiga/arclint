# oh-my-pi: Extension Architecture and TypeScript Execution

Research report, 2026-08-10, for the arclint multi-language design. Every claim carries its source link inline; [INFERENCE]/[RECOLLECTION] labels mark statements not directly verified.

## (a) Identity and purpose

**oh-my-pi** ("omp") is real: [github.com/can1357/oh-my-pi](https://github.com/can1357/oh-my-pi), MIT, 23,401 stars, created 2025-12-31, last pushed 2026-08-10, homepage [omp.sh](https://omp.sh) ([GitHub API](https://api.github.com/repos/can1357/oh-my-pi)). Its README states it is "a fork of [Pi](https://github.com/badlogic/pi-mono) by [Mario Zechner](https://github.com/mariozechner)," rewritten as a coding-first surface ([README.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/README.md)) — though GitHub records `"fork": false` (a detached rewrite, not a tracked fork).

Language composition: TypeScript 48,592,027 bytes, Rust 5,195,090, Python 2,965,610 ([languages API](https://api.github.com/repos/can1357/oh-my-pi/languages)). The README describes ~80,000 lines of Rust across crates `pi-natives`, `pi-shell`, `pi-ast`, `pi-iso`, `pi-voice`, `pi-walker`, plus a vendored `brush` bash fork and 58 CLI utilities compiled into a builtins crate.

A second, unrelated [KrabWW/oh-my-pi](https://github.com/KrabWW/oh-my-pi) exists ("engineer-centric AI Agent framework based on pi-coding-agent"); can1357's is the one matching the description "rust, typescript, SDK extensions".

## (b) Extension mechanism, end to end

**Location** ([docs/extension-loading.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/extension-loading.md)): project-level `<cwd>/.omp/extensions/`; user-level `~/.omp/agent/extensions/` (or `~/.omp/profiles/<name>/agent/extensions/`); plus arbitrary paths via `config.yml` or CLI flags.

**Discovery order** (same doc): native auto-discovered modules, then hook-capability factories, then installed plugin entries from `package.json` manifests, then explicitly configured paths (CLI, then settings). Deduplicated by absolute path, first occurrence wins. Auto-discovery accepts `.ts`/`.js` only; explicit and plugin entries also accept `.mjs`/`.cjs`; directories resolve `index.ts` then `index.js`.

**API surface** ([docs/extensions.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/extensions.md)): a file default-exports `export default function (pi: ExtensionAPI) { ... }`. Registration methods include `on(event, handler)`, `registerTool`, `registerCommand`, `registerShortcut`, `registerFlag`, `registerMessageRenderer`, `registerProvider`. Runtime actions (`sendMessage`, `exec`, `appendEntry`, `setActiveTools`, `setModel`) throw `ExtensionRuntimeNotInitializedError` if called during load — registration and execution are separate phases. Handlers receive an `ExtensionContext` with `ui`, `cwd`, `sessionManager`, `models`, managed timers, and optional `memory`. Events span lifecycle (`session_start`, `session_compact`), turn flow (`before_provider_request`, `turn_end`), and tool execution (`tool_call` can block; `tool_result` can patch).

**Loading** ([legacy-pi-compat.ts](https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/src/extensibility/plugins/legacy-pi-compat.ts)): `loadLegacyPiModule()` resolves the realpath, registers Bun plugin hooks, then calls `` import(`${entrySpecifier}?mtime=${nextLegacyPiLoadTag()}`) `` — the query string forces a fresh module identity so `/reload` picks up edits in-process.

## (c) TypeScript execution runtime

**Bun, embedded in the shipped binary.** `packages/coding-agent/scripts/build-binary.ts` delegates to `compileCodingAgent`, which calls `Bun.build({ entrypoints, compile: { target, outfile }, ... })` — the programmatic form of `bun build --compile` ([compile-binary.ts](https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/scripts/compile-binary.ts)). Cross-targets are `bun-darwin-arm64`, `bun-darwin-x64`, `bun-linux-arm64`, `bun-linux-x64-baseline`, `bun-windows-x64-baseline` ([build-binary.ts](https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/coding-agent/scripts/build-binary.ts)). The artifact embeds the Bun runtime — and therefore Bun's TypeScript transpiler.

Extension TS is transpiled by that embedded transpiler: the Bun `onLoad` hook returns `{ contents: rewrittenSource, loader: getLoader(sourcePath) }` where `getLoader()` yields `"ts"` for `.ts`/`.mts`/`.cts`; the CommonJS path uses `new Bun.Transpiler({ loader: "ts" }).transformSync()` (legacy-pi-compat.ts). No `tsc`, no jiti, no esbuild — root `package.json` lists none of them ([package.json](https://raw.githubusercontent.com/can1357/oh-my-pi/main/package.json)).

Contradicting evidence, stated plainly: `packages/coding-agent/package.json` declares `"engines": { "bun": ">= 1.3.14" }`, and [docs/user-facing-packages.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/user-facing-packages.md) says the npm packages require Bun 1.3.14+. [INFERENCE] Those constraints govern the `bun install -g` and from-source paths; the `curl https://omp.sh/install | sh` and Homebrew paths deliver the `Bun.build({compile})` binary, which by construction carries its own runtime. Basis: the compile target list and README's per-platform binary matrix. `omp.sh/install` returned HTTP 403, so the installer's dependency checks were not verified directly.

## (d) zod

It is **not** zod. `pi.zod` is described as a "Zod-compatible builder backed by omptype" (docs/extensions.md); zod is absent from the root dependency list (package.json). [`@oh-my-pi/omptype`](https://raw.githubusercontent.com/can1357/oh-my-pi/main/packages/omptype/README.md) is "Fast, ArkType-compatible schema validation… Schemas start with a small interpreter and lazily compile after repeated use," exposing `.toJsonSchema()` with `target`/`dialect`/`fallback` options. Three authoring facades sit on one runtime: `pi.zod`, `pi.arktype`, `pi.typebox` ([docs/custom-tools.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/custom-tools.md)).

The pipeline is schema, then JSON Schema, then per-provider normalization: `toolWireSchema()` calls `toJsonSchema()`, prunes `T | undefined` branches, and closes objects with `additionalProperties: false` ([docs/omptype-guide.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/omptype-guide.md)); then `normalizeSchema` "upgrades inputs to JSON Schema 2020-12, dereferences the tree, then walks it," dispatching `adaptSchemaForStrict` (OpenAI), `normalizeSchemaForGoogle`, `normalizeSchemaForCCA`, `normalizeSchemaForMCP`, `sanitizeSchemaForOllama` ([docs/ai-schema-normalize.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/ai-schema-normalize.md)).

**Correction to the premise:** LSP is unrelated to schema generation here. [docs/lsp-config.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/lsp-config.md) opens "This guide explains how to configure language servers for the OMP coding agent" — external language servers for code intelligence, exposed as agent tools. Neither zod nor schema generation appears in it. Config *validation* does use omptype ([docs/config-usage.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/config-usage.md)), but no published JSON Schema driving editor completion was found ([docs/settings.md](https://raw.githubusercontent.com/can1357/oh-my-pi/main/docs/settings.md)).

## (e) Portability to a Go single binary

**Portable (pure logic/data):** the directory precedence and dedupe-by-realpath discovery rules; the two-phase register-then-run lifecycle; the event taxonomy with blocking `tool_call` and patching `tool_result`; and — most valuable — the schema-to-JSON-Schema-to-per-consumer normalization walker, which is data transformation with no JS dependency. The single-binary-with-embedded-runtime distribution shape is exactly what Go does natively.

**JS-dependent:** the transpiler is the whole trick. omp gets TS execution free because Bun's compiled binary contains Bun. [RECOLLECTION, not verified in this research pass] esbuild is itself written in Go and exposes a `Transform` API with a TS loader, so a Go host can strip TS types in-process, then execute the JS on an embedded engine (goja, pure Go; or QuickJS via cgo). Material uncertainty: those engines provide a JS dialect, not Node — no npm graph, no native addons, limited async — so omp's ability to let extensions `import` real packages does not transfer. Also non-portable: `z.infer`-style compile-time type inference has no Go analogue; the Go equivalent is reflection-driven schema generation from structs. Do not replicate the zod-compat facade — replicate the invariant that one schema definition yields both runtime validation and consumer-normalized JSON Schema.

### Modules

- **cmd** — CLI entrypoints: command wiring, output formatting, exit codes. (paths cmd/**; internal imports allow: config, engine, report, ext, patterns, langs, tree, ruletest)
- **config** — rules.yaml data model, JSON Schema pipeline, and validation. (paths internal/config/**; internal imports allow: exprenv)
- **engine** — Rule evaluation: walks the tree, runs every provider, collects violations. (paths internal/engine/**; internal imports allow: config, golang, langs, tree, report, exprenv, ext)
- **exprenv** — expr-lang environment and compile-time type checking for expr rules. (paths internal/exprenv/**; internal imports none (may import no other declared module))
- **ext** — TypeScript extension runtime: esbuild transpile, sobek sandbox, SDK. (paths internal/ext/**; internal imports none (may import no other declared module))
- **golang** — Exact Go import extraction and classification (go/parser). (paths internal/lang/golang/**; internal imports allow: tree, langs)
- **langs** — Shared import model plus the per-language analyzers. (paths internal/lang/**)
- **oracle** — Differential oracle against `go list` over pinned real repositories. (paths internal/oracle/**)
- **patterns** — Embedded architectural pattern bundles served by init and patterns. (paths internal/patterns/**; internal imports none (may import no other declared module))
- **report** — The violation model and its stable JSON shape; stdlib-only. (paths internal/report/**; internal imports none (may import no other declared module); external forbid)
- **ruletest** — Rule test runner: materializes fixture cases and asserts complete violation sets. (paths internal/ruletest/**; internal imports allow: config, engine, report)
- **src** (paths internal/**)
- **tools** — Code generators: stdlib tables, JSON Schema, SDK type declarations. (paths tools/**; internal imports allow: config)
- **tree** — Repository walker: exclusions, file metadata, deterministic order. (paths internal/tree/**; internal imports none (may import no other declared module))

### Query commands

- `arclint context <path|module>` — architectural context of a location (`--format json`)
- `arclint explain <kind|type>` — terminal docs for any rule kind
- `arclint check . --only <id|ns>` — verification scoped to one rule id or namespace

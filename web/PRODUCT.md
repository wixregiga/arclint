# ArcLint Studio

Studio is the place to write and evolve a project's domain language. Its map
shows recorded concepts and their connections. Feature writing is a second
surface where that same language stays at hand and new meaning can emerge.

Stakeholders and developers can define and refine meaning directly, or discover
it while describing application behavior. Neither flow is required to come first.
Definitions, aliases and connections should be easy to retrieve without leaving
the current task. A recognized phrase is a cue, not proof of the writer's intent.

Studio uses the project's actual configured domain recording through ArcLint's
existing application operations. It does not keep a parallel canonical vocabulary.
Rule creation and architecture-rule navigation remain developer tooling.

The visual starting point is BWrite's established light authoring workspace:
quiet neutral surfaces, teal action color, readable prose, a navigator and a
contextual language inspector. Absorb useful behavior into ArcLint's web package;
do not modify the BWrite repository.

The first complete implementation unit is domain authoring: open a project,
load or begin its language, create/edit/remove entries deliberately, see recorded
connections and compare current entries with the default-branch recording.
Features and their persistence follow only after that path passes its gates.

Adopter domains supply the content. Exercise at least two unrelated recordings,
an empty recording and unavailable host capabilities. Stakeholders should not
need architecture paths, test metadata or a new handoff form to describe meaning.
